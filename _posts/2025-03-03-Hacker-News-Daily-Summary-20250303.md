### 20. API design note: Beware of adding an "Other" enum value

 > The article warns against adding an "Other" value to enums in API design, as it creates ambiguity when new values are introduced later. For example, if a new enum value (like "Mint") is added, older code expecting "Other" for unrecognized values may break, while newer code expects explicit handling. ### 24. Why do we have both CSRF protection and CORS?

 Score: 166 Comments: 82 [Link](https://smagin.fyi/posts/cross-site-requests/)

 > The article explains that CSRF (Cross-Site Request Forgery) protections prevent unauthorized actions via cross-site requests, while CORS (Cross-Origin Resource Sharing) allows controlled cross-origin resource access. Browsers enforce the Same-origin policy, permitting cross-site writes (e.g., form submissions) but blocking cross-site reads unless explicitly allowed via CORS headers. The introduction of `SameSite=Lax` cookies reduces CSRF risks by limiting cookie sharing, but adoption varies across browsers. CORS applies to modern JS-based requests but not traditional form submissions, requiring CSRF tokens for security. Both mechanisms coexist, relying on browsers to enforce policies as the web evolves toward stricter defaults.
